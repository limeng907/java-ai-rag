# RAG 质量评测说明

`tools/evaluate-rag.py` 创建独立测试知识库，上传 30 篇短的合成文档，运行 60 个有答案问题、5 个资料外问题。它调用实际上传、Worker、Embedding、向量检索和 Agent 接口。每个正例指定唯一预期文档，主题覆盖相似集合类、Spring 事务与 AOP、数据库索引和 Redis 持久化等易混主题。语料是合成的，因此基线只适用于该固定集。

| 指标 | 定义 | 限制 |
| --- | --- | --- |
| Recall@5 | 60 个正例中预期文档 ID 出现在前 5 个检索 Chunk 的比例 | 文档级命中，不保证 Chunk 句子支持答案 |
| 预期来源出现率 | 默认抽样 5 个正例中，Agent 引用包含预期文档的比例 | 只检查 ID，不证明答案受到 Chunk 支持 |
| 仅引预期来源率 | 抽样正例中全部引用只指向预期文档的比例 | 合理的跨文档对比也会被判不满足，不能称为引用正确率 |
| 无答案误引率 | 5 个资料外问题中，Agent 返回任一知识库引用的比例 | 需人工阅读回答，判断是否编造或误拒答 |

人工复核引用正确率时，用结果中的文档 ID 调用 `/knowledge/documents/{id}/chunks`，逐条将回答的事实断言和被引用 Chunk 原文对照，记录 `支持 / 不支持 / 无法判定`。报告应同时列出分母、模型、Embedding 模型、Chunk 策略、运行时间和失败样本。版本切换与跨用户隔离已有 V8 数据库回归；若将它们纳入本评测，应另外记录其结果，不能并入 Recall@5。

运行前需要应用可用、测试 JWT 可用、Ollama 模型就绪。`python tools/evaluate-rag.py --dry-run` 只检查固定集规模；真实运行可能产生模型调用费用。脚本不会删除创建的知识库，结果文件保存文档 ID 和回答文本，但没有凭证。完成后可通过知识库管理 API 删除测试数据。
