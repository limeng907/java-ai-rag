# V8.9 长对话记忆

本版本保留完整的已提交聊天记录，通过增量摘要恢复关键背景，通过近期消息保留细节，并在每次模型调用前执行上下文预算检查。摘要是有损压缩，不保证自动恢复任意旧细节；原始消息仍通过现有分页接口查阅。本阶段没有引入向量记忆。

## 组成与范围

| 类 | 职责 |
| --- | --- |
| `agent/AgentMemory` | 保留原入口，校验用户归属和消息版本、读取摘要与历史、缓存近期消息 |
| `agent/memory/MemoryRepository` | 一致性快照、摘要边界查询、CAS 更新、失败重试与缓存清理记录 |
| `ConversationSummarizer` | 提交后的有界后台摘要任务，禁止业务工具，限制输入、输出与超时 |
| `ContextBuilder` | 组装唯一的 System Prompt 和当前问题，把历史助手 JSON 投影为参考内容 |
| `TokenBudgetManager` | 估算消息、工具定义、调用参数和工具返回的大小，整轮移除历史或安全失败 |

历史摘要用于 CHAT/STUDY 会话。INTERVIEW/EVALUATION 原有状态和回合持久化保持原流程；共享 Runtime 的预算检查同样适用。

## 摘要边界

默认未摘要消息达到 20 条时触发，保留最近 10 条。20 条消息会摘要 1～10；到 30 条时更新到 20；到 40 条时更新到 30。阈值包含最近保留部分，不是“较老消息达到 20 条”。

消息 ID 是全局序列，允许有间隙。使用同一 `execution_id` 下的 USER/ASSISTANT 两条消息确定完整轮次，摘要边界始终落在已处理轮次的助手消息上。

读取上下文时查询摘要边界之后的消息，不固定只取最近 10 条。例如摘要覆盖到 30、当前有 48 条时，读取 31～48，而不是遗漏 31～38。积压过多时，前台最多读取最新 100 条未摘要消息，后台从边界后顺序分批处理，每批最多 100 条，并受 Token 预算进一步限制。超出读取上限的旧原文仍可分页查询。

旧摘要与新纳入的完整轮次合并生成新摘要。输出固定为五个字符串数组：`userStatements`、`preferences`、`topics`、`openQuestions`、`historicalAssistantSuggestions`。校验输出完整性和大小后，一次性保存文本与边界。空、非法、超限、超时和工具调用输出均不推进边界。

首次插入使用 `ON CONFLICT DO NOTHING`；更新同时匹配 `user_id`、`version` 与旧 `last_message_id`。冲突后读取当前状态，丢弃旧生成结果，留待后续重试。保存时短暂锁定会话，防止删除与摘要保存产生复活记录；模型调用期间不持有数据库事务或行锁。

## 提交与恢复

消息和执行结果提交之后才刷新缓存、提交后台摘要任务；外层事务存在时通过提交回调执行，回滚不发布任务。摘要线程池 2 个线程、队列 32；模型调用线程池 2 个线程、队列 2。同一进程内同一会话任务合并；跨进程通过数据库 CAS 保证不会覆盖较新摘要。

后台每 30 秒扫描待摘要会话，任务完成或失败后设置 60 秒扫描退避；后续成功对话也可重新触发。进程退出或队列满不会丢失原文，扫描可以补做。提供方超时后即使忽略线程中断继续返回，也没有保存摘要的路径；持续不响应的调用最多占满独立的有界线程池，不会占用前台模型线程池。

摘要不是可信用户档案，也不是本次执行的证据。历史 JSON 中的结构化旧证据、引用和题目 ID 不直接回放，只保留回答及学习计划文字。用户自述与历史助手建议明确区分；不能因为询问某个知识点就断言用户不掌握。V8.8 的本次证据注册、工具权限和提交前复核继续生效。

## Token 与字符预算

默认运行预算 65536、输出预留沿用 4096、安全余量 2048、有工具时额外预留 4096。65536 是本项目可配置的运行预算，不是对提供方模型上下文规格的声明；更换模型时应将其设置为不超过实际可用窗口。

默认估算器按 UTF-8 字节数保守估算文本，并附加消息/工具封装开销；中文与英文不会统一按“4 字符 = 1 Token”换算。这不是精确 tokenizer，可能提前拒绝实际仍能容纳的请求。估算器可以替换；提供方仍可能因其内部封装和模型差异拒绝请求。

每轮模型调用前计算 System Prompt（含输出格式）、当前问题、工具定义、工具参数、工具结果、摘要、历史及输出预留。先删除最老的完整历史轮次，再删除摘要；系统指令、当前问题和本次工具消息不截断。仍超限时返回现有错误码 `6002`。原 `max-context-chars: 48000` 作为额外保护继续保留。

摘要调用也有独立输入上限 48000、输出上限 2048，并受共享窗口与安全余量约束。不能容纳一个完整轮次时安全失败并保留原文，不截断 JSON 或虚假推进边界。持久化超过 24000 字符的消息明确拒绝，不再静默裁剪；旧版本已经裁剪的内容无法恢复，非法旧 JSON 在上下文中会明确标记。

## Redis 一致性与删除

数据库是唯一持久化来源。迁移为会话增加 `message_version`，消息插入触发器在同一事务内递增版本，回滚也会回滚版本。消息为追加式记录；直接修改历史行不属于受支持的业务写入路径。

缓存包含版本、前驱边界和最近 10 条原始消息，TTL 随机分布于 90～150 分钟。每次读取先在数据库快照中确认用户归属、消息版本和摘要边界，只有缓存版本匹配且完整覆盖未摘要部分时才能命中；否则回源并回填。刷新失败保留的旧缓存不会继续被当作最新历史。

每个应用实例最多 8 个并发记忆读取/刷新；超限快速返回 `6001` 或跳过刷新。Redis 连接超时 500ms、命令超时 750ms。它们限制局部回源负载，不能替代部署层面的全局限流。

删除会话时摘要通过外键级联删除，缓存清理意图与数据库删除一起提交。提交后删除 Redis，失败由后台重试；回滚不删除缓存。即使残留缓存或并发旧读取迟到回填，已删除会话也不能通过归属查询，缓存最终由清理或 TTL 移除。这里不承诺 PostgreSQL 与 Redis 跨系统原子提交。
