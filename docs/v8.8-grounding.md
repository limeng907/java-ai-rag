# V8.8 Grounding 与可追溯证据

实施日期：2026-10-19。按照审查后确认的七项修订实施，范围为 Agent CHAT/STUDY 的结构化输出及工具证据链。

## 1. 改动目标和边界

V8.7 检查引用 ID 是否出现过；V8.8 进一步检查证据来自哪个工具、属于哪种业务记录、支持哪些结构化事实，以及引用提交时是否仍有效。

本阶段不增加业务工具，不引入第二个模型核查步骤，不提高模型调用次数或超时预算，不重构旧 V7 聊天接口和面试评分模型。
INTERVIEW/EVALUATION 仍复用原执行状态和工具权限；知识工具共享更严格的数据库来源复核，但不强迫其改用学习计划的输出 DTO。

数据库中的评分是已经保存的评价结果，其中可能来自先前 AI 评分，不是客观能力真值。
结构化事实一致性、精确引用和有限的主题关联检查，不等价于对全部自然语言结论完成事实核查。

## 2. 代码职责

| 文件 | 责任 |
| --- | --- |
| `agent/evidence/EvidenceType.java` | INTERVIEW、WEAKNESS、QUESTION、KNOWLEDGE |
| `agent/evidence/EvidenceRecord.java` | 证据身份、来源工具和调用、正文、不可变属性快照 |
| `agent/evidence/EvidenceRegistry.java` | 单次执行的编号、类型化解析、工具结果封装、冻结、引用集合 |
| `agent/validation/AgentEvidenceValidator.java` | 结构化事实、原文摘录、引用类型和有限关联性校验，补全后端事实 |
| `agent/runtime/ToolExecutionAuditor.java` | 在模型看到结果前生成证据，审计及快照接受成功后再返回 |
| `agent/AgentRepository.java` | 原始业务查询、证据持久化、数据库来源与提交前复核 |
| `agent/AgentRuntime.java` | 注册表生命周期、可信约束、校验与一次修正、返回冻结结果 |
| `agent/AgentService.java` | 保存事务内重新检查来源，再保存消息或计划与 FINISHED |

保留已有 validation 包，不重复创建另一个同名校验器，也不为了目录结构迁移记忆模块。

## 3. 实际执行流程

1. 后端创建 executionId，绑定用户与本次指定的知识库范围。
2. ToolPolicy 完成整批工具与参数校验，ToolContext 注入服务器身份。
3. 执行只读工具，取得真正的业务或检索结果。
4. 后端按工具的固定结果结构生成 H/W/Q/K 编号；不递归搜集任意 JSON 中的 ID。
5. 在短事务中锁定仍有效的执行，保存完整的有限证据快照，并把该工具标记成功；超时则回滚。
6. 模型收到带 evidence 和不可信数据标识的工具消息，根据其中的编号生成结果。
7. 校验字段、引用、事实及关联性；不通过最多修正一次，并禁止重新检索。
8. 通过后由后端补全事实和知识来源，冻结注册表，进入 VALIDATED。
9. 业务保存事务锁定执行和会话租约，复核被引用来源的权限、当前状态及身份，成功后原子提交消息、计划与 FINISHED。

证据快照属于执行审计，允许在最终业务失败时保留已经成功取得的证据；不是把未验证的学习计划提前落库。
不接受失败工具、超时工具或迟到结果作为后续模型和业务提交的依据。取消后注册表冻结，迟到证据不能进入已结束的执行流程。

## 4. 证据身份与持久化

编号只在 executionId 范围内有效，例如 W1 不能脱离所属执行单独解释。数据库主键为 `(execution_id,evidence_id)`。
记录包含 type、sourceId、toolName、toolCallId、content、attributes；用户身份和允许的知识库范围由运行时绑定，不能由模型指定。
attributes 使用防御性拷贝，注册表在输出通过后冻结，不接受继续注册。

| 类型 | 可代表的内容 | 不能代表的内容 |
| --- | --- | --- |
| INTERVIEW | 完成会话、跳过、非低分错答的观察记录 | 自动证明某个具体知识点薄弱 |
| WEAKNESS / TURN | 已完成面试中低分或错答回合的记录 | 未涉及主题的能力、整个人的能力真值 |
| WEAKNESS / SESSION_SUMMARY | 历史整场评价中的薄弱点文字 | 不存在的轮次、该轮分数或作答正确性 |
| QUESTION | searchQuestions 实际返回的题目 | 仅在其他文本里出现的题目 ID |
| KNOWLEDGE | 经过数据库来源复核的知识片段 | 模型自行声明的来源或伪造版本 |

逐轮来源使用 sessionId 和 turnId，不依赖可能变化的题目文本充当身份。查询补充了 turnId、correct 及有上限的缺失点文本。
跳过记录作为未作答观察，不创建能力薄弱证据；高分且正确的回合也不直接创建薄弱证据。
历史缺少逐轮记录时，可以保留标记为 SESSION_SUMMARY 的总结证据，但不能填写不存在的逐轮事实。

证据持久化新增 `agent_evidence`，不依赖 agent_tool_call 中最长 8192 字符的截断输出重建。
每次执行最多 120 条证据；每次返回模型的工具消息仍不得超过 24000 字符，上下文仍不超过 48000 字符。
证据正文不在 attributes 中重复存储；原始工具数据不会在模型消息中与证据正文反复复制。

`GET /agent/executions/{id}` 在原 tools 字段之外新增 evidence 审计列表，仅执行所属用户可访问。
执行删除时快照通过外键级联清理；快照遵循执行审计保留策略，并不因文档替换就改写历史。
历史快照不能当成当前可见版本重新提交，引用权限仍要按当前状态复核。

## 5. 兼容输出结构

保留原来的 message、weaknesses、plan、sources，Weakness 的 sessionIds 和 PlanDay 的 questionIds 也不删除。
新字段缺失时可反序列化为空列表，因此原消息、已有 JSON 学习计划和原 Java 构造调用仍可读取。
兼容读取不代表放宽新生成结果的证据校验。

### 薄弱点

```json
{
  "topic": "HashMap",
  "reason": "根据本次引用的历史评价，建议复习扩容机制",
  "sessionIds": [101],
  "evidenceIds": ["W1"],
  "facts": [{"evidenceId": "W1", "quote": "HashMap"}]
}
```

每个 evidenceId 必须有唯一对应的 facts，quote 必须原样存在于证据 content；sessionIds 集合必须与所引证据一致。
facts 可填写 sessionId、turnId、round、score、correct、skipped，但所有填写值必须与证据一致，未知字段不能臆测。
后端会把可用事实补全后再返回和保存，例如真实分数为 45 而模型填 90 时必须拒绝；不通过一次修正则不保存。
reason 是受证据约束的分析文字，不保证自动识别其中任意措辞的隐含事实或过度解读。

### 题目推荐

```json
{
  "day": 1,
  "topic": "HashMap",
  "minutes": 45,
  "tasks": ["复习扩容并练习"],
  "questionIds": [20],
  "recommendations": [{"questionId": 20, "evidenceId": "Q1", "reason": "题目涉及当天复习的 HashMap"}]
}
```

questionIds 与 recommendations 必须一一对应。来源必须是本次题库工具的 QUESTION 证据，不能通过写推荐理由绕过主题关联检查。
关联规则使用明确技术词或中文主题原文匹配，排除单独的 Java、基础、复习等泛词。规则不是语义相似度模型，可能保守地拒绝合理同义表达。
无法确定时，修正提示要求去掉该题目与推荐，保留基础任务；不会自动扩大检索预算。

### 精确知识引用

模型可以只提交 `citations:[{"evidenceId":"K1"}]`，后端填充已核实的元数据。
如果模型主动填写 scope、source、documentId、version、chunkId、contentHash，任何不一致都拒绝。
sources 必须等于 citations 对应的去重来源名称，不能只填一个真实文件名就绕过精确引用。

私有引用包括 Long documentId、Integer version、UUID 文本 chunkId、source、contentHash、PRIVATE scope。
公共知识不冒充私有文档：documentId 和 version 为 null，使用 PUBLIC scope、source、实际 chunkId 及内容 SHA-256 标识。
同版本重新索引可能改变 chunkId，不能把旧的索引尝试片段作为当前有效片段复用。

## 6. 来源复核与并发版本变更

知识工具不直接信任向量结果附带的全部元数据。它按 chunkId 从数据库重新读取，并检查：

- 公共知识必须属于 knowledge-sync-v1。
- 私有知识必须属于 knowledge-document-v1，文档及知识库属于当前用户，知识库在本次请求选定范围内。
- 私有文档当前 READY，片段 published=true，片段版本等于 active_version，关联的版本记录存在。
- userId、knowledgeBaseId 元数据必须与实际关联记录一致。

提交前对被引用知识再次复核完整身份、内容哈希和来源。文档已删除、失去授权、旧版本未发布、片段被替换或来源改变时拒绝提交，不拿旧快照冒充当前资料。
题目提交前也检查存在性及内容快照；面试证据检查当前用户归属、已完成状态和逐轮结构化事实。

保存时先锁定文档，再锁定知识片段；DocumentWorker 激活事务也先锁定文档，再切换片段和版本，避免与引用复核形成相反锁顺序。
不在整个模型调用期间持有这些数据库锁。若提交前证据失效，执行失败，不自动重跑模型或绕开 60 秒预算。

## 7. Prompt Injection 边界

工具消息以 JSON 封装，并标明 REFERENCE_DATA_NOT_INSTRUCTIONS；文档、历史、题目与用户档案文本都不具有修改权限的权力。
运行时系统约束优先声明本次证据契约，数据库活动 Prompt 和资源后备 Prompt 同步升级。
真正的越权拒绝仍由 ToolPolicy 的工具及参数白名单、ToolContext 的服务器身份和数据库归属复核实现。
即使模型听从恶意文档尝试传 userId=2，参数校验也会拒绝，不执行其他用户的数据查询。

这不承诺模型永远不受恶意文本影响。诱导输出无关内容仍需持续测试，但恶意文本不能提升数据库与工具权限。
