# V8.7 AgentRuntime 与 Tool Calling 实施说明

后续 V8.8 在保留本文执行预算、状态及超时约束的基础上，升级了证据模型与数据库迁移。当前 Grounding 字段、校验和部署结果见 [V8.8 实施说明](v8.8-grounding.md)。本文测试计数和启动记录属于 V8.7 当时的验证结果。

实施日期：2026-10-19。本文对应用户确认后的六项修订，不增加新的业务工具，不迁移现有记忆实现。

## 1. 范围与职责

保留五个只读工具：`getInterviewHistory`、`analyzeWeaknesses`、`getUserProfile`、`searchQuestions`、`searchKnowledge`。
写消息、保存计划、保存面试评价仍由业务服务负责，模型不能执行这些写操作。

| 文件 | 职责 |
| --- | --- |
| `agent/AgentRuntime.java` | 编排模型和 Spring AI ToolCallingManager，解析与校验输出，只返回待提交结果 |
| `agent/runtime/ToolPolicy.java` | 场景白名单、STUDY 必需证据、整批参数预检 |
| `agent/runtime/ExecutionBudget.java` | 调用次数、字符、总期限、单次期限与永久取消标志 |
| `agent/runtime/ToolExecutionAuditor.java` | 包装工具回调，记录开始、结果、异常及未执行调用 |
| `agent/runtime/AgentExecutionRecovery.java` | 定时回收过期且没有提交结果的执行 |
| `agent/validation/AgentEvidenceValidator.java` | 原有引用与学习计划规则的独立校验 |
| `agent/AgentRepository.java` | 状态转换、事务内完成、终态保护、回收 SQL |

没有为目录整齐而增加接口或迁移 `AgentMemory`。工具协议执行仍使用 Spring AI，而非自行拼装供应商协议。

## 2. 工具权限与严格参数

CHAT、STUDY 可用全部五个工具；INTERVIEW、EVALUATION 只允许题库和知识检索。未知场景拒绝。

| 工具 | 模型可传参数 | 约束 |
| --- | --- | --- |
| `getUserProfile` | `{}` | 不接受额外字段 |
| `analyzeWeaknesses` | `{}` | 不接受额外字段 |
| `getInterviewHistory` | `limit` | JSON 整数，1 至 5 |
| `searchQuestions` | `keyword`、`limit` | 非空字符串，最长 100；JSON 整数，1 至 10 |
| `searchKnowledge` | `query` | 非空字符串，最长 1000 |

所有列出的参数均必填。拒绝字符串数字、浮点数、null、缺失或未知字段、重复 JSON 属性、多个顶层 JSON 值。
参数必须为 JSON 对象，原始字符串最长 4000 字符。整批预检通过后才执行第一个工具，避免半批已经执行才发现后续参数不合法。
工具调用 ID 不得为空白，最长 200，并且在本次执行内唯一。

`userId`、`knowledgeBaseIds`、`executionId` 只从后端 ToolContext 注入；模型传入这些字段会被拒绝，不会替换授权上下文。
工具内部的原有数量和摘录长度上限仍保留。参数不合法返回 6003；越权工具、调用数量和 ID 冲突返回 6002。
预检拒绝的调用不会写成已运行工具，失败原因体现在执行记录中。

## 3. 预算与收尾

默认值不变：

```yaml
agent:
  max-model-calls: 6
  max-tool-calls: 12
  max-context-chars: 48000
  max-output-tokens: 4096
  timeout-ms: 60000
  call-timeout-ms: 20000
  recovery-delay-ms: 30000
```

前四次模型请求可以检索；第五次保留给最终输出，第六次仅在需要时用于一次修正。
这不是强制用满六次：证据齐全且输出合格时可提前结束。
工具次数用满也会进入收尾阶段；收尾及修正请求不再提供工具。
若模型在收尾阶段仍返回工具调用，直接拒绝，不追加调用或绕过证据校验。
提前生成的输出不合格时，也只允许一次无工具修正，不重新开启检索。

STUDY 进入收尾前必须已成功取得档案、历史、薄弱点三个工具的本次结果。缺失则返回 6002，不浪费保留的生成调用。
成功返回空历史数组是有效证据，不等于工具未调用或失败。此时要求输出说明缺少面试依据，允许基础七日计划，`weaknesses` 为空。
服务端继续校验 sessionIds、questionIds、sources 必须来自本次工具结果，以及七日完整性和每日时长。
自由文本说明仍由提示词约束，服务端的结构化引用校验不等价于对全部自然语言断言的事实核验。

自定义 `max-model-calls` 最少为 3，确保至少一次检索机会与两次收尾预算；其他非法预算在启动时拒绝。
保留调用次数不代表额外增加时间或字符额度；上下文或总时间耗尽时仍失败，不能保证任意长度的检索结果都有剩余修正空间。

## 4. 状态与业务事务

主要路径：`INIT -> THINKING -> TOOL_CALL -> THINKING -> GENERATING -> VALIDATED -> COMMITTING -> FINISHED`。
工具循环可以出现多次；无须调用工具时可以跳过 TOOL_CALL；失败进入 FAILED 或 TIMED_OUT。

| 状态 | 含义 |
| --- | --- |
| VALIDATED | 结构、字段和业务证据校验完成，尚无业务提交 |
| COMMITTING | 业务服务准备提交，可对外查询；不是完成证明 |
| FINISHED | 业务数据和最终状态在同一事务提交 |

Runtime 不能再直接标记 FINISHED。业务服务先把 VALIDATED 转成 COMMITTING，再开启短事务：

1. 锁定执行行，确认状态及执行期限，阻止回收和过期结果提交。
2. 校验原有会话租约或面试 revision 与租约。
3. 写消息、计划或面试数据。
4. 同一事务写 FINISHED、committed_at、finished_at。

CHAT 和 STUDY 的消息及计划、面试首次建会话、每轮回答和最终评价均接入此流程。
纯规则的第二次连续跳过、无有效回答的零分结算仍不调用模型，也不伪造 Agent 执行记录。
评价表新增 execution_id，直接对应本次完成执行；历史评价为空时兼容原有查询方式。

保存任一步失败，数据与 FINISHED 一起回滚，外层再尽力标记 FAILED/TIMED_OUT。
数据库不可用时，失败审计也可能暂时写不进去，因此需要下面的恢复机制。
事务提交后的 Redis 刷新或租约清理异常只记警告，不回退已提交的 FINISHED，也不覆盖原始业务异常。
所有常规状态更新都拒绝覆盖既有终态，完成方法要求处于真实事务中。

## 5. 超时边界

20 秒限制针对一次模型请求或一次完整工具批次，不是每个工具各 20 秒。
60 秒为整次运行期限，业务提交前与最终写入时还会检查数据库执行期限。
运行预算与数据库 expires_at 使用同一个起点，创建审计记录所花的时间不会延长可提交期限。
运行时用单调时钟计时，持久化期限使用 UTC 时间；部署时应保持应用和数据库时钟同步。
这里不是整个 HTTP 请求的硬超时：进入 Runtime 前的鉴权、缓存加载和提交后的响应处理不在此计时范围内。
预算从排队开始计算。超时后设置不可复原的取消标志，取消 Future，并停止接受结果或调度下一工具。
工具回调在进入、返回及写成功审计前检查预算；终态保护还会拒绝迟到的成功审计。

`Future.cancel(true)` 仅请求线程中断，不保证外部 HTTP、JDBC 或第三方代码即时停止。
不响应中断的底层调用可能继续占用工作线程，但其结果不能进入后续模型或业务提交。
线程池仍为 4 工作线程、8 个排队任务，饱和时返回 6001，而非无限扩容。

现有 HTTP 连接 10 秒、读取 20 秒配置保留。JDBC URL 增加连接 10 秒、socket 20 秒、statement 20 秒、lock 5 秒上限；Hikari 获取连接最多 10 秒。
使用环境变量覆盖 datasource URL 时，应保留这些 JDBC 参数或在数据库侧提供等效限制。
这些是分层保护，不承诺所有底层计算在总期限到达的一瞬间物理终止。

## 6. 过期恢复

新增 expires_at 和 committed_at，新增未终态过期索引。默认每 30 秒扫描，单批最多 100 条。
恢复同时要求：执行期限已过、创建已超过 3 分钟、相关业务没有有效租约、没有 committed_at，也没有可关联的消息、计划、已完成回合或评价。
这样不会在 60 秒模型期限刚到时立即处理仍持有 3 分钟业务租约的请求。

候选行使用 FOR UPDATE SKIP LOCKED；业务事务已锁住的执行会跳过。
回收状态和 RUNNING 工具审计通过同一条 PostgreSQL 数据修改 CTE 原子更新为 TIMED_OUT/6008。
恢复是幂等的，不重跑模型、不执行工具、不保存遗留生成内容、不接管新租约。
旧版本已经标记 FINISHED 的历史记录不自动改写，因为无法仅凭状态可靠重建当时的业务提交事实。

## 7. 数据库升级

不要重跑或编辑已经应用的 003。新增迁移为 `db/postgresql/004_agent_runtime.sql`，执行一次。
它为现有记录初始化过期时间，保留全部业务数据；不修改历史终态，也不回填虚构的 committed_at。

先备份数据库，再执行：

```powershell
Get-Content .\db\postgresql\004_agent_runtime.sql -Raw -Encoding UTF8 |
  docker exec -i my_pgvector psql -U postgres -d java_rag -v ON_ERROR_STOP=1
```

迁移在一个事务中执行。该脚本不是可重复执行的迁移框架：升级前查询列是否已存在，避免重复执行。
应用启动前必须先完成迁移；如需回退程序，应保留数据库新增列，不建议在有新评价关联时删除列。
